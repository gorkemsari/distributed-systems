Structural patterns define how services and their supporting components are organized and deployed. This chapter details patterns that allow developers to separate core business logic from infrastructure concerns like logging, security, and protocol translation.

### Topics Covered

* **[6.2.1. The Sidecar Pattern](/distributed-systems/en/microservice-patterns/structural-patterns/sidecar-pattern/)**: Explains deploying helper components alongside the main service to provide modular, reusable infrastructure features.
* **[6.2.2. The Ambassador Pattern: Helper Container as Proxy](/distributed-systems/en/microservice-patterns/structural-patterns/ambassador-pattern/)**: Covers offloading network tasks like circuit breaking and monitoring to a dedicated proxy container.
* **[6.2.3. The Adapter Pattern: Standardized Interfaces](/distributed-systems/en/microservice-patterns/structural-patterns/adapter-pattern/)**: Details how to normalize diverse service outputs (logs, metrics) into a unified format for monitoring tools.
* **[6.2.4. Anti-Corruption Layer (ACL): Integration with Legacy Systems](/distributed-systems/en/microservice-patterns/structural-patterns/anti-corruption-layer/)**: Discusses building a translation layer to prevent legacy data models from "polluting" new microservice domains.
* **[6.2.5. Shared Library vs. Sidecar: Dependency Management Trade-offs](/distributed-systems/en/microservice-patterns/structural-patterns/shared-library-vs-sidecar/)**: Analyzes the pros and cons of using language-specific libraries versus language-agnostic sidecars for cross-cutting concerns.
