In a cloud-native world, service instances are ephemeral and their IP addresses change constantly. This chapter explores the mechanisms that allow services to find and communicate with each other reliably in a highly dynamic environment.

### Topics Covered

* **[6.3.1. Client-Side Discovery: Eureka, Ribbon](/distributed-systems/en/microservice-patterns/service-discovery/client-side-discovery/)**: Explores how clients query a registry directly to determine where to send requests.
* **[6.3.2. Server-Side Discovery: Load Balancer + Registry](/distributed-systems/en/microservice-patterns/service-discovery/server-side-discovery/)**: Covers the pattern where clients hit a fixed endpoint, and the infrastructure handles the routing to available instances.
* **[6.3.3. Self-Registration vs. Third-Party Registration](/distributed-systems/en/microservice-patterns/service-discovery/self-registration/)**: Compares services registering themselves versus using external agents (like Registrator) to manage the registry.
* **[6.3.4. Consul: Service Discovery + Health Checking + KV Store](/distributed-systems/en/microservice-patterns/service-discovery/consul/)**: Deep dives into a popular tool for multi-datacenter service discovery and configuration.
* **[6.3.5. DNS-Based Discovery: Kubernetes DNS](/distributed-systems/en/microservice-patterns/service-discovery/dns-based-discovery/)**: Explains how standard DNS queries are used within container orchestrators to resolve service names.
* **[6.3.6. Health Check Endpoint Pattern](/distributed-systems/en/microservice-patterns/service-discovery/health-check-endpoint/)**: Details the implementation of standard endpoints that allow registries to detect and remove unhealthy nodes.
