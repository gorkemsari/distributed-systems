Traditional CI/CD pipelines often rely on scripts pushing changes directly into production clusters, leading to configuration drift and security risks. This chapter introduces GitOps, a paradigm where automated software agents continuously synchronize the live cluster state with the declared state stored securely in version control.

### Topics Covered

* **[12.2.1. GitOps Principles: Git as the Single Source of Truth](/distributed-systems/en/deployment/gitops-cicd/gitops-principles/)**: Defines the core tenets of managing infrastructure and applications entirely through declarative Git repositories.
* **[12.2.2. ArgoCD and Flux: GitOps Operators for Kubernetes](/distributed-systems/en/deployment/gitops-cicd/argocd-flux/)**: Compares the leading reconciliation engines that constantly monitor Git and automatically apply state changes to the cluster.
* **[12.2.3. Progressive Delivery: Automated Canary Releases with Flagger](/distributed-systems/en/deployment/gitops-cicd/progressive-delivery/)**: Explores combining GitOps with service mesh metrics to automate the scaling or rollback of canary deployments based on real-time health checks.
* **[12.2.4. Pipeline as Code: Reproducible CI/CD](/distributed-systems/en/deployment/gitops-cicd/pipeline-as-code/)**: Discusses the necessity of defining build, test, and release pipelines programmatically alongside application code.
* **[12.2.5. Artifact Management: OCI Registry and Helm Charts](/distributed-systems/en/deployment/gitops-cicd/artifact-management/)**: Details how to securely build, version, and store immutable container images and deployment templates.
* **[12.2.6. Environment Promotion: Dev to Staging to Production](/distributed-systems/en/deployment/gitops-cicd/environment-promotion/)**: Covers strategies for safely moving code and configuration changes across multi-stage environments using pull requests and automated validation.
