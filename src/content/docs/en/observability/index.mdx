Once a system is distributed into multiple microservices, traditional debugging becomes impossible. When a single user request spans dozens of databases and APIs, you need systemic visibility. This part covers Observability—the practice of understanding a system's internal state from its external outputs—and the Site Reliability Engineering (SRE) principles used to measure and manage production stability.



### Chapters

* **[8.1. The Three Pillars: Logs, Metrics, Traces](/distributed-systems/en/observability/logs-metrics-traces/)**: Explores the fundamental data types required to track requests, measure system health, and pinpoint failures across network boundaries.
* **[8.2. Tools and Standards](/distributed-systems/en/observability/observability-tools/)**: Details the modern cloud-native observability stack, from standardizing instrumentation with OpenTelemetry to gathering kernel-level insights with eBPF.
* **[8.3. SLOs, SLAs, and Error Budgets](/distributed-systems/en/observability/slo-sla-error-budgets/)**: Dives into SRE practices, explaining how to mathematically define reliability targets and balance feature velocity with system stability.
