Apache Kafka has become the industry standard for distributed event streaming. This chapter explores the internal mechanics of Kafka, detailing how it leverages low-level OS features for high throughput, manages cluster state without ZooKeeper, and guarantees safe data processing.

### Topics Covered

* **[13.1.1. Disk-Based Persistence and Zero-Copy Optimization](/distributed-systems/en/case-studies/apache-kafka/disk-persistence-zero-copy/)**: Explains how Kafka achieves in-memory-like speed while persisting messages to disk by utilizing sequential I/O and OS page caches.
* **[13.1.2. KRaft Mode: Eliminating the ZooKeeper Dependency](/distributed-systems/en/case-studies/apache-kafka/kraft-mode/)**: Details the architectural shift to a Raft-based consensus protocol managed entirely within the Kafka cluster.
* **[13.1.3. Consumer Group Rebalancing: Failure Scenarios](/distributed-systems/en/case-studies/apache-kafka/consumer-group-rebalancing/)**: Covers the complexities of dynamically distributing topic partitions among active consumers and handling node failures gracefully.
* **[13.1.4. Exactly-Once Semantics: Idempotent Producer + Transactional API](/distributed-systems/en/case-studies/apache-kafka/exactly-once-semantics/)**: Explores the mechanisms required to guarantee that a message is processed precisely once, even during network failures and retries.
* **[13.1.5. Kafka Streams vs. ksqlDB: When to Use Which](/distributed-systems/en/case-studies/apache-kafka/kafka-streams-ksqldb/)**: Compares the programmatic stream processing library with the SQL-like streaming database built on top of Kafka.
