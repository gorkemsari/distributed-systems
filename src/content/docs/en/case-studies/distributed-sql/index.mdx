Distributed SQL is the category that refused the trade-off everyone said was mandatory: it delivers horizontal scale and strong consistency and familiar SQL transactions at once. It does so by combining nearly every mechanism in this handbook -- consensus per shard, synchronized clocks, two-phase commit layered over Raft groups. This chapter reads Spanner and CockroachDB as the two landmark implementations, showing how TrueTime and hybrid logical clocks solve global ordering and how distributed transactions are made practical over consensus.

* **[13.5.1. Spanner: TrueTime, Paxos Groups, and External Consistency](/distributed-systems/en/case-studies/distributed-sql/spanner-architecture/)**: Covers Spanner's use of TrueTime, Paxos groups, and the external consistency it uniquely guarantees.
* **[13.5.2. CockroachDB: Raft, HLC, and Parallel Commits](/distributed-systems/en/case-studies/distributed-sql/cockroachdb-raft-hlc/)**: Explains how CockroachDB combines Raft, hybrid logical clocks, and parallel commits without atomic clocks.
* **[13.5.3. Distributed Transactions in Practice: 2PC over Consensus](/distributed-systems/en/case-studies/distributed-sql/transactions-2pc-over-consensus/)**: Covers making distributed transactions practical by layering two-phase commit over consensus groups.
* **[13.5.4. Follower Reads and Bounded Staleness](/distributed-systems/en/case-studies/distributed-sql/follower-reads-bounded-staleness/)**: Explains follower reads and bounded staleness that scale reads without violating consistency.
