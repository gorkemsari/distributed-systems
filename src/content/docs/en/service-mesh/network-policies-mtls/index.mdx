Securing distributed systems requires moving past legacy perimeter defenses to a "zero-trust" model, where every internal network hop is explicitly allowed, authenticated, and encrypted. This chapter covers the implementation of strict pod-level firewalls, mutual TLS, and the evolution of cloud-native traffic routing APIs.

### Topics Covered

* **[10.2.1. Kubernetes Network Policy: Pod-Level Firewall](/distributed-systems/en/service-mesh/network-policies-mtls/kubernetes-network-policy/)**: Explains how to restrict communication between namespaces and individual pods to minimize the blast radius of a compromised container.
* **[10.2.2. mTLS: Mutual Authentication and Encryption](/distributed-systems/en/service-mesh/network-policies-mtls/mtls/)**: Details how services cryptographically verify each other's identities and encrypt data in transit without developer intervention.
* **[10.3. Certificate Lifecycle: Cert-Manager, SPIFFE / SPIRE](/distributed-systems/en/service-mesh/network-policies-mtls/certificate-lifecycle/)**: Explores the automated issuance, rotation, and distribution of X.509 certificates required to maintain secure identity across the cluster.
* **[10.4. eBPF Networking: Kernel-Level CNI with Cilium](/distributed-systems/en/service-mesh/network-policies-mtls/ebpf-networking/)**: Analyzes how replacing iptables with eBPF technology dramatically improves network performance and deepens security visibility.
* **[10.5. Ingress vs. Gateway API: Next-Generation Traffic Management](/distributed-systems/en/service-mesh/network-policies-mtls/ingress-vs-gateway-api/)**: Covers the architectural shift from the legacy, overly simplified Ingress resource to the highly extensible, role-oriented Gateway API.
