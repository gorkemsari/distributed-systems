In a dynamic cluster, nodes are constantly joining, leaving, or crashing silently. This chapter explores the complex algorithms used to efficiently disseminate cluster state across hundreds of machines and how to mathematically determine if a quiet node is dead or just slow.

### Topics Covered

* **[7.3.1. Heartbeats and the Science of Timeout Configuration](/distributed-systems/en/resilience/failure-detection/heartbeats-timeouts/)**: Explains the foundational mechanism of pinging nodes to verify life and the trade-offs of setting static timeout windows.
* **[7.3.2. Gossip Protocols: Information Dissemination via Epidemic Algorithms](/distributed-systems/en/resilience/failure-detection/gossip-protocols/)**: Details how nodes infect each other with cluster state updates, allowing rapid, decentralized consensus without a central controller.
* **[7.3.3. Phi Accrual Failure Detector: Viewing Failure as a Probability](/distributed-systems/en/resilience/failure-detection/phi-accrual-detector/)**: Explores moving away from boolean up/down states to a statistical model that adjusts to network conditions before declaring a node dead.
* **[7.3.4. SWIM Protocol: Scalable Membership](/distributed-systems/en/resilience/failure-detection/swim-protocol/)**: Analyzes the specific algorithm used by massive clusters to maintain membership lists with constant network overhead.
* **[7.3.5. Liveness vs. Readiness: The Difference Between Kubernetes Probes](/distributed-systems/en/resilience/failure-detection/liveness-vs-readiness/)**: Clarifies the crucial operational difference between checking if an application has crashed versus checking if it is currently able to serve traffic.
